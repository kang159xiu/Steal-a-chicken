## 三、未执行（列出但不动，等确认）

### 1. `Integer` 共 23 份，6 种语义

| 变体 | 份数 | 判定规则 |
|---|---|---|
| `n > 0` | 1 | ChickenObtainedController |
| `n > 0 and n < math.huge` | 2 | MultiplierPurchase、Prompt |
| `n >= 0` | 2 | TrackShop 控制器/服务 |
| `n >= 1 and n <= 2^53-1` | 1 | PersistenceService |
| `(value, minimum)` | 3+ | EggCollection、EggGrowth、HomeCount |
| `(value, zero)` | 2 | Rebirth 控制器/服务 |
| 其余 `Integer(value)` | 12 | 分散在 SellShop、Economy、Treadmill 等 |

风险：**同名不同义**。例如 0 在其中一部分合法、另一部分非法。统一前需逐个调用点确认语义，不能机械替换。

建议：合并为 `Validation.IsInteger(value, minimum)`，由调用点传 `minimum`（0 或 1）；上限统一用 `2^53-1`。

## 五、第二轮：TheftService 拾取状态合并

### 已执行

| # | 位置 | 处理 |
|---|---|---|
| 6 | `TheftService.SendResult` | `requestOperation` 原为 `not success and (a or b or c) or nil` 单表达式，改为先用 `if` 算出再放入消息 |
| 7 | `TheftService` 的 `InteractionByPlayer` + `HoldByPlayer` | 合并为单表 `Pickups`，一条记录用有无 `startedAtMs` 表示「按住中 / 已松开但交互仍在」 |
| 8 | `TheftService.CancelCallback` | 删除未使用的局部变量 `interaction` |

合并的关键约束（原代码生命周期）：

- 松开按钮（`button_released`）**只清 `HoldByPlayer`**，`InteractionByPlayer` 保留，等鸡过期/移走时由 `ClearRequest` 清理并回包。
- `ClearRequest` 对两张表的删除条件不同：Hold 只看 `rootId + operation`；Interaction 还要 `generation == runtime.Generation`。
- 合并后对应为：`startedAtMs` 清空 = 松开；整条记录删除 = 原 Interaction 的删除条件。

**注意点：** 原代码靠「删表项导致引用变化」让重入复核（`Pickups[playerId] ~= prior`）能察觉中间状态被改写。若改成原地 `record.startedAtMs = nil`，引用不变，复核会漏判。因此松开与 `ClearRequest` 的保留分支都改为**重建记录对象**，维持「状态一变就换引用」的语义。
